# DECISIONS.md — принятые решения (не «улучшать» без обсуждения)

1. **Слои domain / application / infrastructure / ui / app.** Хранилище можно заменить
   (IndexedDB, SQLite, сервер), не трогая UI и логику: меняется только `infrastructure` и `app/services.ts`.
2. **Порты вместо прямых вызовов** (`RawStore`, `Clock`, `IdGenerator`). Время и ID — зависимости,
   поэтому логика детерминирована и тестируется без моков глобальных объектов.
3. **`Result<T>` вместо исключений** для ожидаемых ошибок. Исключения не пересекают границы слоёв.
4. **Версия схемы лежит внутри данных, а не в ключе localStorage.** Ключ остаётся постоянным,
   миграции идут по `schemaVersion`. Данные из будущей версии отклоняются, а не портятся.
5. **Повреждённые данные не затираются.** Сначала копия в `..._backup_<ts>`. Не удалось сделать копию —
   запись в хранилище блокируется, пользователь решает осознанно (двойное подтверждение).
6. **Загрузка состояния выполняется один раз в `main.tsx`**, до React. У неё есть побочный эффект
   (копия), а инициализаторы `useState` в StrictMode вызываются дважды.
7. **Запись: debounce 400 мс + `flush()`** на `visibilitychange`, `pagehide`, Capacitor `appStateChange`, unmount.
   Источник для записи — `stateRef` (всегда свежий), а не замыкание.
8. **Побочные эффекты не внутри `setState`-апдейтеров** (в StrictMode они вызываются дважды).
   Команда применяется к `stateRef.current`, затем `setState(next)`.
9. **`import/resolver` в `eslint.config.js` обязателен.** Без него eslint-plugin-boundaries не видит
   `.ts`-файлы и молча ничего не проверяет. Проверено экспериментом: с резолвером нарушение ловится.
10. **Поиск: NFC, `ё→е`, регистр, пробелы. Диакритика не удаляется**, иначе «й» превращается в «и».
11. **Импорт всегда начинается с копии текущих данных**, есть режимы «заменить» и «объединить»
    (при конфликте ID побеждает больший `updatedAt`). Файл ≤ 3 МБ. Нет копии — нет импорта.
12. **UUID с fallback** на `getRandomValues`: `crypto.randomUUID` недоступен на `http://192.168.x.x`.
13. **`androidScheme: 'https'` фиксируется один раз.** Смена схемы меняет origin WebView — localStorage «исчезнет».
14. **TypeScript 6.0, не 7**: поддержка typescript-eslint ограничена `<6.1`.
15. **Подтверждения — `ConfirmButton`, не `window.confirm`/`alert`** (в WebView ненадёжны, нарушают чистоту UI).
16. **Не реализовано сознательно:** синхронизация между вкладками (в Android одно окно; в браузере
    побеждает последняя запись). Если понадобится — отдельный срез с тестом.
