# DECISIONS.md — принятые решения (не «улучшать» без обсуждения)

1. **Слои domain / application / infrastructure / ui / app.** Хранилище можно заменить, не трогая UI и доменную логику: меняются `infrastructure` и `app/services.ts`.
2. **Порты вместо прямых вызовов** (`RawStore`, `Clock`, `IdGenerator`). Время и ID — зависимости, поэтому логика детерминирована и тестируется без моков глобальных объектов.
3. **`Result<T>` вместо исключений** для ожидаемых ошибок. Исключения не пересекают границы слоёв.
4. **Версия схемы лежит внутри данных, а не в ключе localStorage.** Миграции идут по `schemaVersion`. Данные из будущей версии отклоняются, а не портятся.
5. **Повреждённые данные не затираются.** Сначала копия в `..._backup_<ts>`. Не удалось сделать копию — запись в хранилище блокируется, пользователь решает осознанно.
6. **Загрузка состояния выполняется один раз в `main.tsx`**, до React. У неё есть побочный эффект (копия), а инициализаторы `useState` в StrictMode вызываются дважды.
7. **Запись: debounce 400 мс + `flush()`** на `visibilitychange`, `pagehide`, Capacitor `appStateChange`, unmount. Источник для записи — `stateRef` (всегда свежий), а не замыкание.
8. **Побочные эффекты не внутри `setState`-апдейтеров** (в StrictMode они вызываются дважды). Команда применяется к `stateRef.current`, затем `setState(next)`.
9. **`import/resolver` в `eslint.config.js` обязателен.** Без него eslint-plugin-boundaries не видит `.ts`-файлы и молча ничего не проверяет.
10. **Поиск: NFC, `ё→е`, регистр, пробелы.** Диакритика не удаляется, иначе «й» превращается в «и».
11. **Импорт backup приложения начинается с копии текущих данных**, имеет режимы «заменить» и «объединить» (при конфликте ID побеждает больший `updatedAt`). Файл ≤ 3 МБ. Нет копии — нет импорта.
12. **UUID с fallback** на `getRandomValues`: `crypto.randomUUID` недоступен на `http://192.168.x.x`.
13. **`androidScheme: 'https'` фиксируется один раз.** Смена схемы меняет origin WebView — localStorage «исчезнет».
14. **TypeScript 6.0, не 7**: поддержка typescript-eslint ограничена `<6.1`.
15. **Подтверждения — `ConfirmButton`, не `window.confirm`/`alert`** (в WebView ненадёжны, нарушают чистоту UI).
16. **Не реализовано сознательно:** синхронизация между вкладками (в Android одно окно; в браузере побеждает последняя запись). Если понадобится — отдельный срез с тестом.

## ADR для игры Memory

### ADR-017. Локальное хранение колод и изображений через Capacitor

**Статус:** принято.

**Решение:** пользовательские данные хранятся локально в приватной области приложения через Capacitor. Изображения — отдельные оптимизированные файлы с внутре��ними ID; метаданные колод ссылаются на эти ID. Удаление колоды удаляет связанные изображения. Активная партия не переживает перезапуск. Запись колоды и изображений обрабатывает ошибки; частично сохранённая операция не считается успешной. Так как файловое хранилище и метаданные не имеют общей транзакции, требуется staging, компенсационная очистка и удаление осиротевших файлов.

### ADR-018. Версионированный JSON-формат пользовательской колоды

**Статус:** принято для MVP; точная схема уточняется до реализации.

**Решение:** импорт/экспорт входит в MVP и реализуется в фазе 3. Экспортируется целая колода с изображениями; JSON содержит `schemaVersion`. Импорт создаёт новую колоду, полностью валидирует файл до фиксации и не оставляет частично импортированные данные. Ориентир MVP: не более 15 МБ JSON и до 9 МБ оптимизированных изображений на колоду. Полный контракт, политика повторного импорта и точные лимиты должны быть согласованы перед реализацией.

### ADR-019. Внедряемый источник случайности

**Статус:** принято.

**Решение:** домен не использует глобальную случайность. Все случайные операции получают `RandomSource` с `nextInt(maxExclusive)`; домен не импортирует порт из application. Production-адаптер находится в infrastructure. Перемешивание — Fisher–Yates; тесты используют детерминированный источник. Тот же источник используется ботом и назначением цветов игроков. Seed не сохраняется в первой версии.

### ADR-020. Публичная память бота и обработка ошибок

**Статус:** принято.

**Решение:** бот получает только публично открытые карточки, найденные пары и собственную ограниченную память; доступ к скрытым `pairId` запрещён. Бот запоминает публичные открытия всех участников после того, как незакрытые найденные пары исключены, до 24 закрытых позиций. Повторное наблюдение обновляет свежесть; при переполнении забывается самая старая позиция. Найденные пары удаляются из памяти; текущий незавершённый ход передаётся только как временный публичный контекст. Случайный выбор идёт через `RandomSource`.

Если ход бота завершился ошибкой, ход не передаётся автоматически: партия приостанавливается, пользователю показывается ошибка и доступны действия «Повторить ход бота» или «Выйти в меню». До выбора партия не продолжается.

### ADR-021. Пакетная загрузка и оптимизация изображений

**Статус:** принято.

**Решение:** не более 30 файлов и не больше свободного числа пар за операцию; до 5 MiB на исходник и 100 MiB суммарно, предупреждение свыше 60 MiB. Обработка последовательная, один файл за раз, максимум 16 мегапикселей после применения ориентации. Импорт атомарен для пользователя: staging, фиксация только после обработки всего пакета, очистка staging/осиротевших файлов при ошибке, отмене и запуске приложения.

Цель оптимизации — около 250 KiB, жёсткий предел — 300 KiB (`300 × 1024` байт). Ориентация применяется до проверок, метаданные удаляются. Прозрачность при преобразовании в непрозрачный формат заполняется `#f5f5f5`; изображения не кадрируются. В эталонной области 320×320 с `contain` меньшая отображаемая сторона <64 px отклоняется, 64–<96 px предупреждает, ≥96 px принимается без предупреждения. Пропорции >8:1 разрешаются с предупреждением.

Полная спецификация: [`GAME_SPEC.md`](GAME_SPEC.md). Уточнения по случайности, боту и обработке изображений: [`GAME_SPEC_ADDENDUM.md`](GAME_SPEC_ADDENDUM.md).
