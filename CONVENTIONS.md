# CONVENTIONS.md — правила проекта (читать ПОЛНОСТЬЮ перед любой правкой)

Главный закон: правило, которое не ломает `npm run check`, будет нарушено.
Поэтому почти каждое правило ниже проверяется машиной (ESLint / tsc / Vitest).
Нельзя ослаблять проверки (`eslint-disable`, `@ts-ignore`, правка `eslint.config.js`,
удаление тестов) без явного разрешения пользователя.

## 1. Слои и направление зависимостей
`ui → application → domain`; `infrastructure → application, domain`; `app` видит всех.

| Слой | Что внутри | Запрещено |
|---|---|---|
| `src/domain` | Zod-схемы, чистые функции, миграции, фильтры | React, Capacitor, I/O, `Date.now`, `crypto.randomUUID`, `localStorage` |
| `src/application` | Порты (интерфейсы) и сценарии: загрузка, импорт, бэкап | React, Capacitor, импорт `infrastructure` |
| `src/infrastructure` | Реализации портов: localStorage, часы, UUID, Capacitor | React, импорт `ui` |
| `src/ui` | Компоненты и хуки React | Capacitor, `localStorage`, импорт `infrastructure` и `app` |
| `src/app` | Точка входа и сборка зависимостей (`services.ts`) | Бизнес-логика |

Новая папка в `src/` = сначала обсудить и добавить слой в `eslint.config.js`
(иначе `boundaries/no-unknown-files` упадёт).

## 2. Один файл — одна ответственность
- Файл ≤ 200 строк, функция ≤ 60 строк, ≤ 4 параметров, сложность ≤ 10, вложенность ≤ 3.
- Файл приближается к 150 строкам → остановись и предложи разделение ДО добавления кода.
- Один компонент React на файл. Логика состояния — в хуке (`useXxx.ts`), не в компоненте.
- Имя файла называет его единственную ответственность; общих `utils.ts`, `helpers.ts`, `common.ts` нет.
- Не создавай файлы «на будущее». Не дублируй типы: тип выводится из Zod (`z.infer`).

## 3. Данные
- Любые внешние данные (localStorage, импорт) идут ТОЛЬКО через `parseAppState`
  (миграция → Zod → проверка целостности). Читать `JSON.parse` где-то ещё нельзя.
- ID: только через порт `IdGenerator` (`ids.next()`); время: только порт `Clock`.
  Доменные функции получают `id` и `now` аргументами и остаются чистыми.
- Связи между сущностями только по ID. Удаление родителя каскадно чистит ссылки (`deleteTagCascade`).
- Изменение формата данных = новый шаг в `domain/migrations.ts` + повышение
  `CURRENT_SCHEMA_VERSION` + тест на «золотом» файле старой версии. Без этого формат не менять.
- Повреждённые данные никогда не затираются молча: сначала копия (`writeBackup`).

## 4. Ошибки
- Ожидаемые ошибки возвращаются как `Result<T>` (`ok` / `err`), а не бросаются.
- Исключения перехватываются только на границе с внешним миром (infrastructure) и превращаются в `Result`.
- Пользователь всегда видит причину отказа (баннер/сообщение), `console.log` запрещён.
- `any`, `as`-приведения «чтобы заткнуть компилятор», `!` (non-null) запрещены.

## 5. React
- Вычисляемое не хранится в state: фильтры, счётчики — считаются при рендере.
- `useEffect` — только для подписок и синхронизации с внешним миром, с обязательной очисткой.
- Сброс формы при смене сущности — через `key`. Список — `key={entity.id}`, не индекс.
- `dangerouslySetInnerHTML`, `eval`, `window.alert/confirm` запрещены (XSS и ненадёжны в WebView).
- Методы интерфейсов объявляются как свойства-функции: `save: (x) => Result<void>`.

## 6. Тесты
- Новая доменная функция или сценарий = тест рядом (`name.test.ts`) в том же коммите.
- Тест фиксирует поведение, а не реализацию. Баг сначала воспроизводится тестом, потом чинится.
- Для application и ui используются подделки из `application/fakes.ts`, а не реальный localStorage.
- Нельзя «чинить» красный тест, подгоняя ожидание под неверный результат: сначала объясни почему
  поведение должно быть именно таким.

## 7. Зависимости и версии
- Новые npm-пакеты только с разрешения пользователя. Версии зафиксированы в `package-lock.json`.
- Не используй API, в существовании которого не уверен: открой типы в `node_modules` или
  попроси пользователя прислать документацию. Не угадывай.

## 8. Протокол работы ИИ
1. Перед кодом: план (какие файлы создаются/меняются, какие тесты, какие крайние случаи).
2. Меняй только файлы из утверждённого плана. Нужен другой файл — остановись и спроси.
3. Выдавай файлы ПОЛНОСТЬЮ: никаких `// ...`, `// TODO`, «остальной код без изменений».
4. После правок обнови `ARCHITECTURE.md` (если появился/исчез файл) и `PROGRESS.md`.
5. Готово = `npm run check` зелёный. Если не удаётся исправить за 2 попытки — стоп, откат, новый чат.
